Tunebatch, sequences

LM Studio calls these Physical Batch Size and Max Concurrent Predictions (its default is 4).

what seqs changes It sizes the recurrent state on hybrid models and the sliding-window cache on SWA models (Gemma, Mistral, gpt-oss) — llama.cpp allocates one window per sequence slot, so four slots is four windows.

what it costs This model ships multi-token-prediction blocks. LM Studio turns this on by default for them (Speculative Decoding: MTP, llama.cpp --spec-type draft-mtp). It gives the draft blocks a KV cache back — at f16 regardless of your KV quant — plus a per-sequence slot. Untick only if you set Speculative Decoding to Off.

×

Leave this ticked on CUDA. It matters more than the image size does. Derived, not measured — unlike everything else here.

why the tick box beats the image size The projector's weights are charged above. This reserves what the encoder needs while it runs. Unfused, that is quadratic in pixels — attention is n_head × n_patches², so a 2560×1600 screenshot at 16px patches is 16,000 patches and several GiB, and halving each side cuts it ~4×. Fused, the quadratic term vanishes.

On CUDA, clip.cpp resolves CLIP_FLASH_ATTN_TYPE_AUTO by probing the backend, and the SigLIP tower these models share (head dim 72) is a supported size — just not on the tensor-core path. Untick it for a backend without a working FA path, to see the ceiling. Either way this is a default, not a measurement: your load log's flash attention is enabled/disabled line settles it. Note LM Studio's own Flash Attention toggle applies to the language model, not the tower.

Advanced, llama.cpp -ot only. Leave off to model a normal LM Studio split.

BUDGETS

These answer different questions, and picking the second means the plan and any measured row were priced differently.

why total is the default A speed campaign refuses to start unless the card is essentially empty, so free VRAM at planning time is transient state the measurements will never be taken under. Planning against it produces a split that no recorded row can match — which is exactly the disagreement the recommendation card at the top reports when you switch this to free.

RAM budget defaults to total installed, since a model can load into standby/paged memory. The header shows what is free now; the plan warns if it exceeds that.

Headroom on top of the plan, and the basis a speed campaign is seeded with.

what is already accounted for The CUDA context and driver overhead are already inside the compute-buffer estimate - they were fitted together against measured loads - so the reserve is for something else wanting the card, e.g. your desktop. It defaults to 512 MiB because that is what the speed sweep plans against, and the two disagreeing by any amount moves the recommended split.

SPEED MODEL

KV is re-read every token, so speed depends on how full the context actually is — not on the size you allocated. RAM efficiency is set by Calibrate.
